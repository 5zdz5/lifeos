# Agent Pet OS 概念 → LifeOS 落地说明（W5）

> 白皮书提出 9 大核心概念与 4 套工程防御。本文逐条讲清**每个概念在 LifeOS 里的真实落点、复用的工程锚点、以及诚实边界**。
>
> **总原则：注入灵魂，不改骨架。** 不新增顶层导航（仍 12 项）、不新增源文件（仍 35 个）、不新增实体键（仍 6 个）——所有能力作为内嵌逻辑与既有模块的增强接入，由第 14 套件 `pet.test.js` 守护这些硬不变量。
>
> 版本：`vc04360fc` · 内核 `L.pet`（内嵌于 `src/js/utils.js`），独立 key `lifeos-pet-v1` 持久化。

---

## 内核设计：`L.pet`

一个纯逻辑命名空间，所有视图只依赖它的 API，browser/electron 无感（对齐 `L.bridge` 的分层思路）。

| 能力 | API | 工程防御 |
|---|---|---|
| 状态持久化 | `load/save/get/update` | 独立 key 与主数据解耦；损坏自动回落默认、**不污染任务/笔记**（故障隔离） |
| 名册 | `addPet/setActive/activePet` | 64 只上限、字段白名单收敛、非法 id 回落 |
| 装备专家 | `equip/equipActive/gearOf` | 装备 id 白名单，非法值拒绝 |
| 点头授权 | `approvalFlow/requestApproval` | 双阶段不可跳过、各阶段带 Trace ID、无 DOM 时**保守拒绝** |
| 数字分身 | `observe/userSkills` | 只认真实行为，不凭空编造偏好 |
| A2A 社交 | `inbox/traceId` | 每条消息带校验状态、trace-id 唯一 |

## 9 大概念逐条落地

### ① 具身化智能体
- **界面落点**：总览顶部桌宠伙伴面板——分层 SVG 团子生物，呼吸/眨眼动效，情境化说话气泡（基于真实待办数与时段），点头像回应。
- **工程锚点**：`app.js` 的 `L.petRenderer`；动画在 `prefers-reduced-motion` 下归零但信息不丢失。
- **诚实边界**：这是**内联 SVG 的具身化界面**，不是 Pixi.js/骨骼动画；"对话"复用现有 AI 助手通道，无独立语音唤醒。

### ② 吞噬与知识内化
- **界面落点**：知识库每张卡片「◈ 吞入内化」按钮→转成结构化卡片笔记，摘要/要点/标签齐全，并自动把**同标签的已有笔记**用 `[[标题]]` 写进「关联」段。
- **工程锚点**：`library.js` 的 `internalize()`，复用 `L.links`（Obsidian 双向链接）与 `L.store`；行为经 `L.pet.observe` 沉淀。
- **诚实边界**：吞的是**知识库条目**，不是任意本机文件拖拽（网页版不碰磁盘， Electron 文件读写是另一条链）；链接基于标签匹配，非语义相似度。

### ③ 具象化建房子
- **界面落点**：知识图谱新增「⌂ 知识小屋」布局开关，节点沿屋顶→屋檐→墙→地基坐标铺开，连线勾勒屋子轮廓。
- **工程锚点**：`graph.js` 的 `houseLayout()`，与原有 `layout()` 力导向并存；**不改** `g-edge`/`data-open`/两处 `U.stagger` 契约。
- **诚实边界**：是坐标布局模式，非物理引擎力导向"生长动画"；屋子成形需要真实的内化笔记做节点。

### ④ 装备与专家系统
- **界面落点**：总览装备栏 + AI 助手装备栏，5 种专家（通用/学者帽/清道夫/庄家领结/分身面具），戴上即改 `activePet.equip`。
- **工程锚点**：`ai.js` 的 `buildSystem()` 按装备注入不同 System Prompt 人格与职责边界（如清道夫"只能建议、不能擅自删"）。
- **诚实边界**：装备改变的是**人格与提示词**，不是真正加载/卸载插件沙箱；插件执行仍走既有 Codex/bridge。

### ⑤ 安全授权（点头原则）
- **界面落点**：总览「点头授权演示」+ Codex 删除任务，均走**双阶段**弹窗：① 子宠物申请 → ② 主控点头，任一阶段拒绝都不执行。
- **工程锚点**：`L.pet.approvalFlow/requestApproval`，每阶段带 `trace:xxx:request/nod`；桌面端提示"由主进程二次核验"。
- **诚实边界**：网页版是**双阶段确认界面**，不能替代 OS 原生弹窗的抗 XSS 能力；白皮书要求的 Rust `native_dialog` 需要独立的 Tauri 桌面端实现，本版如实标注，不伪造"系统级"可信性。

### ⑥ 多宠物生态
- **界面落点**：总览名册 chips（默认小屿/阿净/阿博），可切换、可「＋」领养新宠物并起职责名。
- **工程锚点**：`L.pet` 名册 API，字段白名单 + 64 上限。
- **诚实边界**：宠物是**界面身份与职责标签**，尚未绑定各自独立的调度线程（当前团队仍是本机顺序执行）。

### ⑦ 老板视角与多 Agent 团队
- **界面落点**：Codex 左栏「◆ 团队」开关，展开庄家/Worker A/Worker B 角色看板，实时显示占用状态。
- **工程锚点**：`codex.js` 的 `teamBoardHTML()`，`updateStop()` 局部刷新占用灯（不整页重绘，避免打断输入）。
- **诚实边界**：**如实标注"并发上限 1·本机顺序执行"**——不虚构多进程并发；熔断（最多 3 步）由 Agent 引擎约束，看板只呈现真实形态。

### ⑧ 个人数字分身
- **界面落点**：总览「已从你的行为学到…」；设置页数字分身摘要；AI 助手 System Prompt 注入偏好。
- **工程锚点**：`L.pet.observe/userSkills`，6 个习惯探针（连成网络/长成小屋/派发任务/重视授权/夜间工作/爱复盘），命中即沉淀。
- **诚实边界**：偏好来自**本地行为计数**，非向量检索/长期对话提取；与既有「识海记忆」互补（识海管原话，分身管偏好摘要）。

### ⑨ 多平台与社交（A2A）
- **界面落点**：设置页「多平台·社交」区——三端形态（本机桌面/网页/鸿蒙）、跨宠物来信（带"已校验"）、唯一 trace-id、模拟来信按钮。
- **工程锚点**：`L.pet.inbox/traceId`；`settings.js` 的 `socialSectionHTML()`。
- **诚实边界**：**本地演示**——三端数据各自存本机，未接云端账号/端到端加密；来信是模拟数据，不连接真实 social-gateway。

## 4 套工程防御 → 用户看到的画面

| 灾难 / 防御 | 界面如何表达 |
|---|---|
| 网关 8s 超时 → Mock 降级（防空壳） | 沿用既有 AI/采集失败提示与演示标注；W5 新增能力均本地运行、无网可降级 |
| XState 5s 强制回 Idle（防卡死） | 桌宠说话气泡与装备操作是瞬时状态，不留无限转圈；点头授权两段弹窗可 Esc 取消 |
| LangGraph `recursion_limit=3`（防烧钱） | 团队看板明示"单任务最多 3 步由引擎约束"、名额 1/1 |
| Rust 原生弹窗（防伪造） | 前端气泡（暖、软）与主控点头（明确第二段、带 trace）在文案与层级上刻意区分；如实说明网页版不能替代 OS 原生框 |

## W5.1 · 视觉强化（解决"看不出变化"）

首版把桌宠塞进普通卡片、9 概念散落各处，视觉上仍是效率工具，用户反馈"看不出变化"。W5.1 只改 `app.js` / `style.css`，不动内核与骨架：

- **桌宠英雄化**：舞台升为总览主角，形象放大到 156px、加静态径向光环（缩放不做旋转/斜切）、"伙伴在线"胶囊、以及 4 格**真实互动统计**（内化/连线、搭屋、点头、聊天，全部来自 `L.pet.stats()`，不编造）。
- **9 概念能力带**：总览新增一条 `concept-strip`，9 个概念各占一格（图标+名称+落点），全部可点击直达对应视图；数据来自渲染常量，路由走既有 `data-go`，不新增导航项。
- **无障碍与降级**：新增动画在 `prefers-reduced-motion` 下归零，形象与信息完整保留；配色全走 `var(--...)`/`color-mix`，能力格支持键盘焦点。
- **验证**：浏览器实机 14/14（英雄区 7 项 + 能力带 4 项 + 点击路由 2 项 + 零报错 1 项），深色/浅色双主题零裁切零重叠 → `docs/pet2-dashboard-dark.png`、`pet2-dashboard-light.png`。

> 设计判断：**功能是"有没有"，视觉是"看不看得见"**。W5 解决了前者，W5.1 让 9 个概念从"藏在菜单里"变成"摊在第一屏"。

## W5.2 · 缓存击穿（解决"发布了却看不到变化"）

首轮视觉强化后用户反馈"和之前根本没变"。排查：三方 hash 完全一致（本地 = 版本清单 = 线上），线上代码确为最新、全新浏览器可见新版——**根因是浏览器里的旧 Service Worker 把旧 `app.js`/`style.css` 缓存住了**：SW 对静态资源走 cache-first，而资源 URL 从无版本串，旧 SW 拿旧 URL 命中旧缓存，界面永远不刷新；地址栏 `?v=` 没进资源 URL，破不了缓存。

- **根治**：构建期给 index.html 的本地 CSS/JS 引用注入 `?v=<hash8>`，让每次发布的资源 URL 唯一，旧缓存 key 天然 miss；SW 静态资源策略改为网络优先、失败回退缓存。
- **无循环**：`contentForHash` 计算版本时剥离 index.html 的版本串，避免"版本串→内容变→版本变"死循环；`build.test.js` 幂等/无循环断言全绿。
- **验证**：持久化 profile 里先植入伪造的旧缓存（无版本串 key），再打开新版——资源 URL 带版本串、旧 app.js 未被加载、英雄区与 9 能力带全部呈现，9/9 通过 → `docs/pet3-cache-busted.png`。
