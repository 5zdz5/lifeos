# ADR-002 · 零依赖 CSS 单源构建，且不做规则级删除

- **状态**：已实施（W1 构建链 / W3 收敛评估结论，2026-11-13）
- **相关**：`tools/build-css.js`、`src/css/style.css`、`src/css/finesse.css`、`src/css/app.css`、`src/index.html`、`build-standalone.js`

## 背景

项目最初在 `index.html` 同时引 `style.css`（基础层）与 `finesse.css`（finesse 设计系统覆盖层），造成运行时双层加载、覆盖顺序隐式依赖、standalone 内联与 SW 缓存清单各写一份、改动容易漏同步。

W1 计划引入构建工具合并 CSS，但环境里没有 esbuild、`node_modules` 为空；拉取未审查的第三方二进制包会触发供应链门禁。方案允许「依赖审查不通过则降级自研零依赖脚本」。

W3 时统计到合并产物有 896 条规则、**跨文件重复选择器 185 处**，需要给出「是否做规则级收敛」的结论。

## 决策

1. **零依赖确定性合并**：`tools/build-css.js` 按固定顺序拼接 `style.css → finesse.css`，加来源分隔注释与生成统计，`merge()` 幂等；只依赖 Node 内置 `fs`/`path`
2. **单一运行时来源**：`index.html` 只引一份 `css/app.css`；`build-standalone.js` 内联同一份；`app.css` 标为生成物禁止手改
3. **保留全部旧类名与源文件顺序**，W1 不改任何规则，视觉零风险
4. **W3 结论：不做规则级破坏性删除**（见下）
5. 构建文案如实标注「跨文件重复为有意层叠覆盖」，不写误导性的「待收敛」

## 为什么不做规则级收敛

| 理由 | 说明 |
|---|---|
| 重复是**有意层叠** | 185 处大多是「基础层定义 → 设计系统覆盖层重定义」，删掉会改变视觉或让基础层单独引用时失样式 |
| 运行时单一来源已达成 | W1 之后两份源 CSS 只是**构建输入**，不再双载；重复不产生运行时开销，只有约几 KB 文本 |
| S3 硬判据是零视觉破损 | 规则级删除需要 11 张逐张回归背书，收益远小于风险 |
| 层叠顺序敏感 | 两个源文件中间可能插入其它规则，简单按选择器去重会破坏层叠语义 |

## 备选方案

| 方案 | 未采用原因 |
|---|---|
| esbuild / postcss 合并压缩 | 环境未安装，需联网拉未审查依赖，触发供应链门禁 |
| 按选择器去重（保留后出现的规则） | 破坏基础层独立可用性与层叠语义，视觉风险高 |
| 把 `finesse.css` 内容手工搬进 `style.css` | 丢失分层，后续无法按设计系统迭代 |

## 后果

**正面**：100% 可复现、零第三方依赖、构建/standalone/SW/鸿蒙 rawfile 四处天然一致；`tests/build.test.js` 用 8 条断言固化顺序/完整性/幂等/零依赖。

**负面 / 代价**：`app.css` 约 94.7 KB 未压缩；`version.json` 仍记录 3 个 CSS 文件（两份源 + 一份产物），SW 会缓存两份运行时不加载的源 CSS（约 90 KB 冗余缓存）。

## 撤销条件

满足**全部**才可重新评估：① 引入带 AST 级层叠分析的 CSS 构建器且通过依赖审查；② 能提供「删除前后 11 张逐像素比对一致」的证据；③ 49 项发布一致性与 91 条浏览器回归零回归。

## 证据

`npm run build:css` 输出「规则 896 处（跨文件重复 185 处，为有意层叠覆盖）」；`tests/build.test.js` 8 条；`tests/w3.test.js` 幂等与单源断言；`.ai-memory/handoff.md` W3 章节 CHECKPOINT-10。
